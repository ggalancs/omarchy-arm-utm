Arch Linux ARM · Hyprland · UTM en Apple Silicon

Construir Omarchy ARM

Omarchy 4 no se puede instalar en ARM64. Esto reconstruye su escritorio sobre Arch Linux ARM, en una máquina virtual aarch64 nativa acelerada con HVF, desde macOS y con un solo comando.

Solo quiero la VM

Descarga omarchy-arm-utm-v2.zip del Internet Archive (3,6 GB), doble clic, y arranca sola.

10 minutos + la descarga

Quiero construirla yo

./build-omarchy-arm.sh y contestar con Enter, salvo tres decisiones.

1 h — 1 h 50

1 Qué necesitas

Mac con Apple Silicon La VM es aarch64 nativa con HVF. En Intel habría que emular y tardaría un día. uname -m → arm64
Homebrew El script instala qemu, expect y aria2 si faltan. brew --version
UTM 4.7 o posterior Es donde queda registrada la máquina virtual. brew install --cask utm
Command Line Tools De ahí vienen git y python3, que el script usa para calcular la lista de paquetes. xcode-select -p
~40 GB free El directorio de trabajo llega a unos 24 GB de pico, y los clones de APFS pueden empujarlo más arriba. df -h ~
Conexión decente Descarga ~900 MB de imágenes base y luego unos 1.500 paquetes de los repos de Arch Linux ARM. —

Si falta algo:

# git y python3
xcode-select --install

# Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

brew install --cask utm
No hace falta sudo. El script no toca nada del sistema anfitrión: todo lo que necesita lo escribe dentro de su directorio de trabajo, y las tres dependencias de Homebrew se instalan con tu usuario.

2 Qué contexto necesita

Ninguno: es un solo fichero. build-omarchy-arm.sh lleva embebidos los quince ficheros que necesita —las tres etapas de instalación, el sanitizador, el reparador, el instalador de apps opcionales, el hook de actualización, la configuración de la VM, los dos arneses de expect, el lanzador de QEMU y el generador del bundle .utm—, más el LEEME que viaja dentro del zip. Los escribe en disco al arrancar. Puedes copiar solo ese fichero a otro Mac y funcionará igual.

Lo único que puedes darle de antemano, para ahorrarte ~900 MB de descarga, son las imágenes base: 

mkdir -p ~/omarchy-arm-build/dl
cp alpine-virt-*-aarch64.iso     ~/omarchy-arm-build/dl/alpine-virt-aarch64.iso
cp ArchLinuxARM-aarch64-*.tar.gz ~/omarchy-arm-build/dl/alarm-rootfs.tgz

El directorio de trabajo es ~/omarchy-arm-build salvo que indiques otro con W=/ruta/que/quieras.

3 Ejecutarlo

$ ./build-omarchy-arm.sh

Y ya está. Con terminal hace primero seis preguntas prerrellenadas con lo que detecta de tu Mac, así que se contestan con Enter:

  Nucleos para la VM [6]:               ← mitad de tus núcleos de rendimiento
  Memoria para la VM (MiB) [12288]:     ← según tu RAM
  Tamano del disco [80G]:

Y luego las tres que sí cambian el resultado:

¿Compilar las 17 herramientas de Omarchy que no existen para ARM?

Si dices que no, el escritorio funciona igual, pero faltarán ttfx (el salvapantallas), tensaku (anotar capturas), omacalc, omacut, omawrite, aether, cliamp y omarchy-nvim. Se añaden después con yay -S.

+40 min

¿Incluir OBS Studio y Pinta?

Son software libre, así que pueden viajar dentro de la imagen, y la que se distribuye los lleva. OBS se compila entero desde fuente (sin el plugin de navegador, cuyo CEF es x86-only) y Pinta necesita el .NET arm64 oficial de Microsoft. Es lo más caro de todo el proceso.

+50 min

¿Preparar la imagen para repartir?

No deja la VM con tu usuario y tu configuración, y se salta las fases sanitize y package. Sí renombra el usuario a omarchy, borra claves SSH, identidad de git e historiales, y genera un .zip con su sha256.

+13 min

Para no responder nada:

$ ./build-omarchy-arm.sh --yes   # no pregunta: construye la imagen lista para repartir

Sin terminal —cron, CI, nohup— tampoco pregunta: detecta que no hay tty y sigue en modo desatendido.

4 Cuánto tarda cada fase

Medido en una construcción real sobre un M3 Max, con las herramientas compiladas y sin OBS ni Pinta.

deps~10 s comprueba el Mac e instala qemu, expect y aria2 si faltan
fetch2 min descarga Alpine y el rootfs de ALARM, verificando sha256 y MD5
prepare~10 s cruza la rama viva de Omarchy con el índice de Arch Linux ARM
build40 min Alpine headless, particionado, rootfs y las tres etapas en chroot
utm1 min escribe el bundle .utm y lo registra en UTM
verify4 min arranca y le exige siete condiciones: Hyprland y quickshell vivos, ≥400 comandos, ≤5 enlaces rotos, ≥6 unidades, versión 4 y el portapapeles completo
sanitize10 min copia el disco y lo limpia para distribuir
package3 min compacta el qcow2, crea el bundle y lo comprime
76–83 min en total → 3,6 GB de .zip ~24 GB de pico en disco con OBS y Pinta incluidos

La fase build no imprime casi nada mientras trabaja. Para verla por dentro: 

$ tail -f ~/omarchy-arm-build/logs/build.log

5 Si algo falla

Cada fase es reanudable, así que no hay que empezar de cero:

$ ./build-omarchy-arm.sh --from build    # reanudar desde ahí
$ ./build-omarchy-arm.sh --only package  # repetir solo una fase
$ ./build-omarchy-arm.sh --list          # ver los nombres válidos

Reanudar no vuelve a preguntar: reutiliza lo que ya decidiste. Los logs quedan en ~/omarchy-arm-build/logs/, uno por fase. El de build es el que importa: lleva la salida completa de las tres etapas dentro del invitado, con los prefijos [stage1], [stage2] y [stage3].

Tres comportamientos deliberados

  • Si ya hay un disco construido, build no lo borra: lo mueve a omarchy-arm.qcow2.anterior y empieza uno nuevo.
  • Si ya existe una VM en UTM con el mismo nombre, no la borra: registra la nueva añadiéndole la hora al nombre.
  • Para que UTM reconozca un bundle nuevo hay que reiniciar la aplicación, porque solo escanea Documents al arrancar. Si tienes VMs en marcha, el script avisa y te deja decidir; en modo desatendido no las corta, y te dice que importes el bundle a mano con Archivo → Importar.

6 Cuando termine

La VM aparece en UTM y arranca sola, sin pedir contraseña.

La tecla Option (⌥) actúa como SUPER, porque macOS se queda con Cmd antes de que UTM lo reciba. ⌥+Space abre el menú de Omarchy, ⌥+Return un terminal, ⌥+K la lista completa de atajos.

Las apps propietarias no vienen dentro —empaquetarlas sería redistribuir binarios de terceros—, pero todas tienen build ARM64 oficial y la imagen trae un instalador que las baja de su fuente: 

$ omarchy-arm-extras --list
$ omarchy-arm-extras          # menú interactivo

1Password, Obsidian, Typora, LocalSend y Google Chrome. Spotify no tiene cliente nativo ARM, pero la web sí funciona: necesita Widevine, que viene dentro de Google Chrome arm64.

7 Si no quieres construirla

La imagen que produce todo esto está publicada, sanitizada y lista para importar: 

# https://archive.org/details/omarchy-arm-utm
# descarga omarchy-arm-utm-v2.zip — 3,6 GB
$ shasum -a 256 -c omarchy-arm-utm-v2.zip.sha256
$ unzip omarchy-arm-utm-v2.zip
$ open "Omarchy 4 ARM64.utm"

Usuario omarchy, contraseña omarchy (también root).

Al lado hay un omarchy-arm-utm.zip de 6,5 GB: es la primera entrega, y conserva el nombre corto para que los enlaces y checksums publicados con ella sigan apuntando a los bytes exactos para los que se escribieron. Esa es la única razón de que la buena lleve -v2 en el nombre. Si ya te descargaste aquella, no necesitas bajar 3,6 GB otra vez: los dos scripts de fixes/ la ponen al día desde dentro.

8 Para deshacerlo

$ rm -rf ~/omarchy-arm-build   # el directorio de trabajo entero

Y borra la VM desde la propia interfaz de UTM. El script no ha tocado nada más de tu Mac.

Trabajo no oficial, sin relación con Basecamp ni con el proyecto Omarchy. Omarchy soporta x86_64; cuando publiquen el ISO aarch64 que ya tienen planificado, esto dejará de hacer falta.
